## Problem Statement

组织层今天是 v1 形态：四席编制（`lead`／研究员／`reviewer-lead`／
`reviewer-second`）、13 stage 双席评审协议、mail 承载任务语义、无任务台账、
无岗位契约件、无任何常驻值守岗、实施面成员空缺（`PLAN-expanded-engineering.md`
「编码方实例：未创建」）。用户要的是**目标→团队自治**的组织：给出目标后团队
自己分诊、编组、派单、互检、结算，用户只在关键裁定点出场；且组织形式本身是
**能力放大器**——全低配模型组合也应完成裸低配模型完不成的任务。

在这个终景下，今天的组织层有七个具体问题：

1. **岗位无契约**。「岗位」只散落在提示词与代码硬编码里，没有可读、可审、
   换模型不变的契约件；模型一升级就要重写提示，组织设计里的模型假设随代
   腐烂。
2. **任务无权威面**。任务的身份、归属、状态与过程散在邮件正文与 session
   历史里——mail 没有任务语义，收单队列超 100 条被静默截断、回合失败不重试
   也无人接住（两处静默丢失有实证坐标）。用户看不到「这单现在谁负责、卡在
   哪、超时怎么办」。
3. **权限无组织面**。mail／knowledge／review 三面都没有授权模型，共享面
   存在多写者与 writer ownership 缺口；`~/.dsh` 全域对 bot 不是零直写，
   「真实运行面零写入」这条纪律没有落到 bot 侧权限面上。
4. **评审形态过重**。13 stage 协议＋双席＋提示层双审注入＋enforcement 矩阵
   机制庞大，而矩阵全 pending、无机械执行；真正需要的是「关键产出有人独立
   复核」，不是一套流程机器。
5. **宿主更迭即静默失效**。前端与接线依赖宿主内部面（cordis 槽名、
   client bundle 结构、私有 DOM 属性），宿主改名或改形状后组织层**不报错
   但做错**——模型/人设静默不生效、UI 静默退回原生，且现有存在性守卫在
   门汇总行上与真通过同形。
6. **人间接口不正式**。关键裁定靠邮件往返，没有权威投递面与裁定包，
   mail 回文可能被当成裁定；用户不在场时组织要么干等、要么自行代裁。
7. **无验收口径**。「规格被完整实现」与「组织形式确实放大能力而非只摊成本」
   都没有可执行判据，无法判定 v2 何时算建成。

## Solution

把组织层重建为一份**以工件为契约**的形式，使「换模型只动岗位细节三处、
组织层件不动」一层可判：

- **岗位集**：4 个常设角色类别＋1 个按需复核角色类别，每岗一张**岗位卡**
  （八字段，含必填的「放大机制」）。岗位是契约单位，实例按需存在；一个实例
  一个 home 岗位、可被项目线短期借用。
- **任务台账**：任务升格为一等对象——host 侧 append-only 事件日志、单一写者、
  状态是事件投影，`taskId` 是 provenance 根。**四要素简报**（目标／输出格式／
  工具与来源／边界＋可执行验收判据）派出即冻结。**复核点是边界事件**而非流程
  阶段。
- **权限四层**：实例基底（用户域旋钮）／文件面（bot 直写仅自身 workspace、
  共享面零直写）／组织命令面（**capability** 岗位化＋台账命令三元组鉴权）／
  人间面（CSRF user principal＝台账全权）。邮件成为**零权威通道**。
- **工具面**：按岗位卡派生注册，**一 op 一工具、工具名即 op 名**——工具面
  裁剪即权限裁剪。
- **人间接口**：单一权威投递面＝**人间收件箱**（台账事件投影，内嵌终裁
  操作）；只有三类裁定进 `waiting-user`，且**无超时自动动作**。
- **记忆与知识**：三层（岗位私有／任务事实→台账／可复用结论→知识库），
  写入三问分流，晋升与失效都有显式规则。
- **宿主适配面**：按**失配后果**分类（A 静默降级／B 响亮／C 非宿主面），
  A 类经可替换适配层＋行为探针；探针三态，**门只由行为断言把守**。
- **恒久性**：组织层件白名单封闭枚举，逐条过**换模型试金石**；模型更迭走
  四步升级例程。
- **一批式切换**：不设双轨期，单窗口内撤旧席→建 v2 双席→就绪探针→最小闭环
  smoke。

## User Stories

### 接单、分诊与立项

1. 作为用户，我希望把目标直接丢给组织就能开工，以便不必自己拆解与派活。
2. 作为用户，我希望组织先走确定性规则、只在语义判断时才动 LLM，以便常见请求便宜且可预测。
3. 作为值班统筹，我希望收单先匹配例程与常驻规则、命中即直办，以便重复请求不重复思考。
4. 作为值班统筹，我希望每次把判断上浮都记录「为什么确定性判不了」，以便上浮可归因、可复盘。
5. 作为值班统筹，我希望分诊产出固定的四值（直办／立项／澄清／拒收），以便下游不必猜意图。
6. 作为值班统筹，我希望目标到达且需编组时拉起项目经理，以便常态值守与目标态编组各归其位。
7. 作为值班统筹，我希望代表组织向用户投递裁定请求，以便人间接口只有一个入口。
8. 作为用户，我希望被拒收或需澄清时收到的是原话直达结论而非改写转述，以便不失真。

### 任务台账与生命周期

9. 作为用户，我希望每个任务有稳定 id 和单一权威状态，以便随时知道「谁在做什么、卡在哪」。
10. 作为项目经理，我希望任务状态是一串事件而不是一个可变字段，以便历史不可篡改、可完整回溯。
11. 作为项目经理，我希望台账只有一个写者（host），以便并发推进不产生互相覆盖。
12. 作为项目经理，我希望派单是「写归属＋接单确认」，以便没人接的单不会躺在那里没人管。
13. 作为项目经理，我希望逾期未接自动释放回队列并通知我，以便单子不静默卡死。
14. 作为项目经理，我希望租约到期自动回收、重派有封顶，以便实例死了任务还能继续。
15. 作为项目经理，我希望重派封顶后上浮用户，以便机器解决不了的事交回人。
16. 作为承接岗，我希望可以带理由拒收派单，以便不合适的任务不被硬塞。
17. 作为承接岗，我希望同一时刻只持一个进行中任务，以便不并行串台、归属永远显式。
18. 作为承接岗，我希望第二条归属被机械拒绝而不是本地排队，以便冲突立刻可见。
19. 作为项目经理，我希望冲突时上抛用户而不在实例内自行取舍，以便取舍权不落到执行层。
20. 作为承接岗，我希望接单即拿到冻结的完整契约，以便不需要靠追问补上下文。
21. 作为承接岗，我希望契约改动只走追加事件并显式通知我，以便不被静默改写简报。
22. 作为项目经理，我希望结算只核判据是否满足、复核是否闭合，以便不重审内容。
23. 作为用户，我希望任务关闭后不可重开、要来新的开新任务并引用旧 id，以便审计链不断。
24. 作为审计者，我希望取消与失败不删档、事件链保留，以便失败也能被复盘。
25. 作为用户，我希望等待我裁定的任务不占租约、不烧 token，以便我几天不回来也不浪费预算。
26. 作为用户，我希望等待我裁定的任务可以无限期挂着而不被组织代裁或放弃，以便关键决定权不被绕过。
27. 作为用户，我希望简报里声明的业务截止时间到期只标「已过期」而不自动取消，以便过期与否由我处置。
28. 作为值班统筹，我希望异常（实例死亡、任务停滞、等用户、等外部依赖）四类统一走台账，以便没有静默丢失。
29. 作为值班统筹，我希望通知都是台账事件的投影、无事件不通知，以便不会收到与状态不符的提示。

### 简报与派单纪律

30. 作为项目经理，我希望简报的四要素与验收判据四非空，以便没有半成品任务被派出。
31. 作为项目经理，我希望验收判据必须可执行，以便「做完了」有机器可判的依据。
32. 作为项目经理，我希望判据不可执行时先分解为可观测项、分解不出来就上浮，以便不接受裸主观判据。
33. 作为项目经理，我希望派单不预置产出方的语义决定，以便取代／沿用／复用等判断权归属产出方。
34. 作为项目经理，我希望派单只给坐标不给转述，以便承接方自己去取最新内容、不被我引入偏差。
35. 作为承接岗，我希望全轨迹由台账持有而不是塞进简报，以便上下文预算不被历史淹没。
36. 作为值班统筹，我希望值守例程以「例程 id＋时间窗」幂等，以便重复触发不产生第二个任务。

### 复核

37. 作为用户，我希望命中必审清单的产出必须被独立复核，以便不可逆或对外可见的动作不裸奔。
38. 作为用户，我希望必审清单只由三条客观判据决定（不可逆／对外可见／跨实例关键产出），以便不靠人工裁量决定要不要审。
39. 作为项目经理，我希望可以加审但不可以免审，以便风险可以升不可以降。
40. 作为复核者，我希望拿到 diff＋判据＋工件本体就够，以便复核不必读产出方的推理过程。
41. 作为复核者，我希望读不到产出方的推理轨迹，以便独立性是机械事实而不是自觉。
42. 作为复核者，我希望复核报告只报 gaps 与严重度带上证据坐标，以便不和风格偏好混在一起。
43. 作为复核者，我希望可以自己跑可执行检查，以便判据结论有机器依据。
44. 作为复核者，我希望不得改工件、不得放宽判据，以便复核不变成代做。
45. 作为复核者，我希望以「契约帽子」形式被当次空闲实例佩戴、不必常驻编制，以便组织不必养评审席位。
46. 作为产出方，我希望同一任务内不得自任复核者，以便自检不自证。
47. 作为用户，我希望复核未闭合的产出被阻断交付，以便问题不外泄到我这里。
48. 作为项目经理，我希望清单外的复核只是咨询性、不阻断，以便不把一切都变成关卡。
49. 作为用户，我希望连续两轮未闭合就上浮给我终裁，以便死循环有人收。

### 权限与能力

50. 作为用户，我希望 bot 只能直写自己的 workspace，以便共享数据面不被绕过 host 直接改。
51. 作为用户，我希望 `~/.dsh` 全域对 bot 零直写，以便注册表、profiles 与其他实例的数据安全。
52. 作为用户，我希望组织命令必须经认证的 host 通道，以便权限边界不在文件系统层面被绕过。
53. 作为用户，我希望 capability 由 host 在状态转移点签发、bot 不能自请，以便授权不自我循环。
54. 作为用户，我希望 capability 单次消费、绑定实例代际身份与任务域，以便窃取的信封在别处不可用。
55. 作为用户，我希望长任务以短 TTL＋心跳续签维持授权，以便长跑不必开大口子。
56. 作为用户，我希望租约回收、取消、关闭时授权自动吊销，以便权限不残留。
57. 作为用户，我希望岗位只决定「可持有哪些 op」，以便权限随契约走而不随代码走。
58. 作为用户，我希望复核帽在 op 集里没有任何写操作也没有台账全量读，以便只读是结构性的。
59. 作为用户，我希望台账命令鉴权是三元组（实例活态／op 白名单／任务域匹配），以便伪造任何一项都被拒。
60. 作为用户，我希望鉴权失败是 fail closed 且记台账事件回错误回执，以便拒绝不静默。
61. 作为用户，我希望邮件内容永不构成权限、状态或事实依据，以便伪造邮件最坏只造成困惑。
62. 作为用户，我希望 capability 不经邮件递送，以便投递通道不会实质变成权威面。
63. 作为运维者，我希望任何岗位都不以 danger-full-access 为履约前提，以便组织不靠取消边界来工作。
64. 作为用户，我希望实例基底权限（sandbox 模式）与任务域授权正交叠加取严，以便两套口径各管各的、不互相替代。

### 工具面

65. 作为实施者，我希望工具名就是 op 名，以便「能用什么工具」和「被授权做什么」是同一件事。
66. 作为实施者，我希望我的工具集由岗位卡派生，以便岗位契约改了工具面就跟着改。
67. 作为维护者，我希望提示段是岗位卡的派生物且构建期校验漂移即失败，以便提示与契约不会分叉。
68. 作为实施者，我希望任务简报在接单响应里拿到而不住在 systemPrompt，以便多任务并行不串台。
69. 作为用户，我希望 mail 的写入收口到 host 中继、bot 侧无 inbox/outbox 直写，以便共享面无多写者。
70. 作为用户，我希望 knowledge 登记命令化、读取面照旧，以便登记进授权面而检索保持低摩擦。
71. 作为复核者，我希望占位探针的判据来自简报里预登记的验收项，以便不能自己报判据。
72. 作为用户，我希望探针白名单机制存在且 fail closed，以便白名单外一律拒。
73. 作为运维者，我希望工具通道失效时走「错误回执／台账事件／进流程」三条明确分支，以便没有文件直写后门。
74. 作为维护者，我希望 v2 没有运行时 skill 装载机制，以便规程只有岗位卡与知识库两种形态。

### 人间接口

75. 作为用户，我希望只有不可逆放行、上浮终裁、用户域裁定请求三类会挂起等我，以便其余进展只是告知、不阻塞。
76. 作为用户，我希望在一个收件箱里看到所有需要我拍的事，以便不必翻邮件找。
77. 作为用户，我希望收件箱里的操作就是台账命令，以便裁定与审计同源、不另起一套命令面。
78. 作为用户，我希望邮件回文永不构成裁定，以便我误回一封邮件不会改变任何状态。
79. 作为用户，我希望裁定包里是冻结简报、判据事实、双方立场、可选动作与后果、模型身份，以便我在最小充分上下文里做决定。
80. 作为用户，我希望裁定包不自动附全文工件而按指针取用，以便不被信息淹没。
81. 作为用户，我希望未命中必审清单的产出可以由便宜模型初审代理处置，以便我的终裁只花在真正需要的地方。
82. 作为用户，我希望初审代理在必审产出上只整理裁定包、不做处置，以便不可逆动作的决定权永远在我。
83. 作为用户，我希望模型指派、越权处置、冲突仲裁三项永不可代，以便组织不能替我决定这些。
84. 作为用户，我希望初审拒绝或判据两轮未闭合时强制上浮，以便代理不能把问题压在下面。

### 记忆与知识

85. 作为岗位实例，我希望在 workspace 里有自由笔记作为私有记忆，以便不需要结构化 schema 也能积累。
86. 作为用户，我希望实例消亡后私有记忆无迁移义务，以便组织不承诺无法兑现的继承。
87. 作为用户，我希望团队共享记忆不另起第三面，以便任务事实走台账、可复用结论走知识库。
88. 作为岗位实例，我希望写入前用三问分流（任务历史事实／跨任务有效／中间产物），以便东西去对地方。
89. 作为岗位实例，我希望推理过程不进任何持久面，以便复核隔离与记忆都不被污染。
90. 作为用户，我希望知识晋升有三条门槛（过换模型试金石／可独立成立／留痕），以便知识库不被当垃圾场。
91. 作为用户，我希望晋升强制性由派单方在输出格式里预声明，以便既不全局强制、也不无人负责。
92. 作为用户，我希望知识失效只有显式取代一种机制、不做自动失效与热字段，以便知识变化可审计。
93. 作为用户，我希望知识与台账冲突时台账胜、与岗位卡冲突时岗位卡胜，以便唯一源不被旁路。
94. 作为用户，我希望移交只传指针、接手方拉取，以便内容传递不被中间人改写。
95. 作为用户，我希望工件归档不删档、无保留期上限，以便历史可追溯。

### 恒久性与模型更迭

96. 作为用户，我希望组织层件是封闭枚举的白名单，以便「哪些文本不许含模型假设」是明确集合。
97. 作为用户，我希望白名单每一条都过「换一个更强模型会不会变成废话或障碍」这一问，以便组织设计不绑代。
98. 作为用户，我希望岗位细节只住三处（岗位卡档位字段／提示段／实例配置），以便换模型时改动面一层可判。
99. 作为用户，我希望模型指派是运行时旋钮、架构只保证解耦与可配置，以便我自己决定哪个岗位用哪个模型。
100. 作为用户，我希望改模型指派后台账自动登记评测任务，以便不依赖我记得手动验证。
101. 作为用户，我希望新模型先跑岗位评测集、再做减法删掉多余的提示约束，以便约束随模型能力自然消退。
102. 作为用户，我希望评测通过后由我终裁是否收编新指派，以便升级不自动生效。
103. 作为维护者，我希望每岗至少有一个可执行的评测项，以便评测集不是空壳。
104. 作为用户，我希望「放大」有可验证表述——裸实例在预算内做不到而组织形式同量级做到，以便形式价值不是口号。

### 宿主更迭

105. 作为用户，我希望宿主面按「改名或改形状后会不会静默做错」分类，以便该保护的才保护。
106. 作为用户，我希望静默降级面必须经可替换适配层把形状收敛到一处，以便宿主改名只改一个坐标。
107. 作为用户，我希望每个 A 类面挂行为探针、真实调用一次并断言结果形状，以便静默失败变成响亮失败。
108. 作为用户，我希望响亮失配面登记后即可直用，以便不为一堆不会静默坏的面加维护负担。
109. 作为用户，我希望非宿主面显式排除并写明理由，以便后人不会把它们重新纳入。
110. 作为维护者，我希望探针结果是三态且跳过必须分列计数可见，以便存在性守卫的假绿被消除。
111. 作为用户，我希望运行面与部署面的「跳过」视同失败，以便宿主不在的无意义放行不被接受。
112. 作为用户，我希望门只由行为断言把守、宿主版本号只作诊断，以便不被 rc 版本号语义绑住。
113. 作为用户，我希望探针失败默认只降级该面、其余能力照常，以便一个面坏掉不等于组织停摆。
114. 作为用户，我希望整层拒载只用于组织层身份面，以便降级策略有明确唯一例外。
115. 作为用户，我希望宿主面失效以例程任务落台账承载处置并告知我，以便故障有主、可见可归因。
116. 作为用户，我希望前端只依赖宿主显式注册面、禁读私有 DOM 与样式钩子，以便宿主 UI 改版不推倒前端。
117. 作为用户，我希望宿主 UI 大改不构成「重做前端」的义务，以便最小可用是功能可操作而非像素一致。

### 切换、验收与回退

118. 作为用户，我希望 v2 一次性切换、不设双轨期，以便「归属必须显式」这条不变量保持可判定。
119. 作为用户，我希望起步编制只要双席就能跑最小闭环，以便切换面尽量小。
120. 作为用户，我希望切换前门全绿、就绪探针通过、且我逐项点名授权，以便大动作在我知情下发生。
121. 作为用户，我希望切换后跑一次真实任务走完全链，以便新组织不是纸面就绪。
122. 作为用户，我希望旧席数据先归档再清运行面，以便可回看且运行面归零。
123. 作为用户，我希望回滚靠部署件备份与提交点、且决定权在我、不预先演练，以便回退是保险而不是流程。
124. 作为用户，我希望验收分两卷：实现完备性逐条可查、能力放大实验一次性执行，以便「建成了」与「有价值」分开判。
125. 作为用户，我希望验收判据在我拍板规格时就冻结，以便不会被事后补判据凑结论。
126. 作为用户，我希望裸对照先跑判定基准集、裸跑成功的任务出集，以便基准集真的都是裸模型做不到的。
127. 作为用户，我希望成本以 token 为主口径、复用已有会话统计，以便不新建账、不做币值换算。
128. 作为用户，我希望放大机制归因只作诊断输出、不参与通过与否，以便评分与影响分离。
129. 作为用户，我希望验收判定只有两态、任一条红即不通过，以便没有「部分通过」的模糊地带。
130. 作为用户，我希望验收结论、失败证据与实验原始数据都落档，以便结论可复算。

## Implementation Decisions

### A. 组织层件与岗位契约

- **五类角色类别**（03）：常设四岗 `duty-coordinator`（值班统筹）／
  `project-lead`（项目经理）／`researcher`（研究员）／`implementer`
  （实施者）＋按需 `verifier`（复核帽）。岗位 slug 英文作契约主键，
  中文为显示名，改显示名不动契约；工具与权限命名空间按 slug 前缀派生。
- **岗位卡八字段**：一句话职责／触发条件／输入输出契约／边界（不做什么）／
  存在理由／**放大机制**（分解·互检·外置·并行，必填——填不出即不设该岗）／
  模型档位（用户域，留空）／依赖面·更迭敏感性（引用宿主适配面登记的**面 id**，
  不重复坐标）。
- **岗位卡是唯一源**，提示段是派生物；插件启动时从岗位卡渲染每岗系统提示段，
  `lib` 内硬编码提示段全部消灭；仓库加构建期漂移校验，卡哈希与渲染产物不一致
  即失败。
- **岗位／编制分离**：岗位是契约单位，实例按需存在；一个实例一个 home 岗位、
  可被项目线短期借用。**不单设岗**：分诊与验收初审挂值班统筹＋确定性组件；
  知识/规程维护挂值班统筹＋「谁产出谁登记」；调度常态归值班统筹、目标态归
  项目经理；模型升级评测归值班统筹；设计并入实施者。
- **组织级不变量**：单一时刻单一任务归属；冲突上抛用户；确定性优先且上浮
  可归因；单入口收单、结论原文直通；验证外置与复核隔离。
- **现役四席无保留义务**，直接按 v2 重建（用户裁定）；前端「原生像素级统一」
  降级为「原生一致优先、功能可用兜底」。

### B. 任务台账（新建面）

- **台账＝host 侧 append-only 事件日志、单一写者**；bot 零直写，只经认证
  host 命令写入；**状态是事件序列的投影**，缓存态仅作优化，重启可从未闭合
  队列的事件重建。`taskId` 是 provenance 根，格式避开评审面旧前缀（v2 用
  `TK-`；旧 `T-`／`J-` 随形态退役）。
- **任务对象统一**：`class: duty|project` 两类同属一个任务对象。三来源＝
  用户目标／外部事件／常态触发；收单先匹配确定性规则表与例程，命中即直办，
  未命中才把语义判断上浮值班统筹。分诊产出四值：直办／立项／澄清／拒收。
- **生命周期**：主干十态 `intake → triaged → planned → assigned → accepted →
  running → produced → delivered → settled → closed`，旁路四态
  `blocked / waiting-user / failed / cancelled`。每个状态必须能回答「下一步
  谁负责、超时怎么办」，答不出即删。**合法性由确定性层校验**（含 CAS
  期望状态不符即拒），LLM 岗位只提交判断输入，**不得直接写状态**。
- **四要素简报**：字段为任务 id／类别／目标／交付物（输出格式＋存放坐标）／
  来源（工具面＋坐标，ID-only）／边界／验收判据／复核点／归属与租约／父任务。
  不变量：四要素与验收判据非空；**判据必须可执行**，不可执行即判据缺口，须先
  分解为可观测项、分解不出来标 `needs-user` 上浮；不预置产出方语义决定
  （方法论 #17）；给坐标不给转述、全轨迹由台账持有（方法论 #16）；**派出即
  冻结**，改动只走 `amend` 追加事件并显式通知承接方。
- **归属与租约**：归属由台账持有（`owner + lease + heartbeat deadline`）；
  派单＝CAS 写归属；被派方须在时限内接单，逾期未接自动释放回队列并通知派单方；
  可带理由拒收；租约到期或实例死亡自动回收，重派封顶后上浮用户；一实例同时
  只持一个进行中任务，第二次归属被机械拒绝。**时限与封顶数值属用户域**，
  规格只要求「必须有这两项与可配置的缝」。
- **结算与关闭**：结算归项目经理（项目）／值班统筹（例程）；关闭前置＝验收
  判据均有可执行检查的通过记录、命中的复核点已闭合、产出已按「谁产出谁登记」
  登记。**关闭即转只读、不可重开**——要改则开新任务并以 `supersedesTaskId`
  引用旧 id。取消权在用户终裁，项目经理可取消但须归因并通知。失败不删档。
- **异常四类统一走台账、不静默丢失**：实例死亡／任务停滞／等待用户／等待
  外部依赖。对应修掉 v1 的两处静默丢失（收单队列超限截断、回合失败不重试）。
- **通知＝台账事件投影，无事件不通知**。
- **值守例程**：声明式登记项（例程 id／触发条件或周期／简报模板／预算缝），
  属组织常量、由值班统筹维护；触发幂等键＝`例程 id＋时间窗`，重复触发不产生
  第二个任务；例程任务的验收判据可由健康探针或回归结果自动生成。
- **投递层要求**：mail 退为投递／通知通道，生命周期对其硬要求＝
  **at-least-once＋幂等**（重建判旧件存废时不得削掉）。

### C. 复核件套

- 形态＝「**必审清单＋判据＋gaps 报告＋修复回合＋上浮**」一件套，**无 stage
  机**；转换权威不再来自确定性阶段投影。
- **必审清单**由三条客观判据枚举：**不可逆**（写入真实运行面／冻结面、
  不可回滚的覆盖或删除）、**对外可见**（交付用户、跨组织提交、外部 API
  写入）、**跨实例移交的关键产出**（下游任务输入工件、判据工件、组织常量
  变更）。命中即强制复核，无人可豁免；项目经理**可加审不可免审**（加审须
  留归因）。
- **复核点是边界事件，不是流程阶段**：命中清单的产出在跨越任一不可撤边界
  之前必须过复核——不可逆写入**之前**、对外可见**之前**、作为下游关键输入
  被移交**之前**；**不在结算处另设一道**。
- **处置分级**：命中清单＝阻断性（gaps 未闭合不得交付／回笼）；清单外＝
  咨询性（处置权在项目经理或用户）。修复走一次性回合；**连续两轮未闭合即
  上浮用户终裁**。
- **判据**由派单方在四要素简报中预登记且必须可执行；复核者只对照判据、并
  另报判据本身的缺口；**可自跑可执行检查，不得改工件、不得放宽判据、不得
  自行改口径**；报告形状固定为「gaps 列表＋严重度＋证据坐标」。
- **独立性**＝复核者读不到产出方的推理轨迹与中间过程，只拿 diff＋判据＋
  工件本体；**fresh context 为硬要求**；模型同异不设硬约束（属模型指派域），
  但复核报告**须记录模型身份**。
- **复核者＝契约帽子**：任意当次空闲实例可佩戴（机械判定＝台账中无进行中
  租约的实例），排除本任务产出方，不设常驻席位；同一任务内产出方不得自任。
- **形态废弃**：13 stage 协议与确定性 stage 机、双席席位、提示层双审注入、
  enforcement 矩阵、试水轮待触发项、旧规程 R-2026-007 随 v2 生效注销（代码
  处置见 §I）。

### D. 权限四层与 capability

- **L0 实例基底**：DSH sandbox 权限模式＋workspaceRoot，**用户域实例旋钮**，
  组织层不接管；岗位卡不硬编码权限模式。组织侧约束一条——**无岗位契约以
  danger-full-access 为履约前提**（全部岗位在 workspace-write 下可履约）。
- **L1 文件面**：bot 直写面＝自身 workspace；**`~/.dsh` 全域对 bot 零直写**
  （注册表／profiles／其他实例 workspace／各数据目录）；共享面读写一律经
  host 命令；冻结面（证据包链）零写只读；跨实例工件移交不经文件系统，走
  artifact 提交。
- **L2 组织命令面**：**capability** 岗位化封装＋台账命令三元组鉴权。
  - **op-set 岗位表**：值班统筹持 `task.intake`／`task.triage`／`routine.*`／
    `ledger.read`；项目经理持 `task.create`／`task.assign`／`brief.amend`／
    `task.settle`／`review.request`／`ledger.read`；承接岗（研究员·实施者）持
    `task.claim`／`task.accept`／`task.report`／`task.escalate`／
    `artifact.read|submit`／`evidence.read|probe`／`ledger.read`；**复核帽**持
    `artifact.read`／`evidence.read|probe`／`results.read`／`review.report`
    ——**无任何写 op、无 `ledger.read`**；人间面（user principal）持台账全权、
    不经岗位 op 表；运维（实例启停／注册表 CRUD／模型指派）为**人间面专属、
    不设岗位 op**。
  - **签发权在 host、由台账转移点驱动**（派单给承接者签发任务能力、复核点
    命中给戴帽实例签发只读能力；**bot 不能自请自签**）；单次消费语义不变；
    长任务＝**短 TTL＋心跳续签**；任务域绑定＝`binding.taskId`；**吊销与生命
    周期联动**（租约回收／取消／关闭／交付→自动吊销对应能力）。
  - **台账命令鉴权三元组**：实例活态（验签＋nonce 单次＋代际绑定＋活态槽
    比对）／op ∈ 岗位白名单／任务域匹配（`binding.taskId` 全等，状态报告类
    命令要求当前租约持有者）。配 **CAS**（命令携带期望状态与序号，不符即拒）
    与**幂等键**。**拒绝＝fail closed 不执行**，拒绝本身记台账事件并回错误
    回执，连续越权通知派单方并计入上浮。
  - **capability 递送不经 mail**，经认证 host 命令通道（如接单成功响应携带）；
    泄漏无害性由实例绑定保证。
- **L3 人间面**：CSRF 令牌＝唯一 user principal（role=user）＝**台账全权**，
  可发一切台账命令、不经岗位 op 表；user 命令与 bot 命令同走台账事件
  （actor 字段区分），可见性不降。岗位实例**不持有** user principal。
- **复核只读面＝op-set 否定式**（读不到写通道即只读）；复核实例自身
  workspace 可写（本地草稿），不触及工件面。与实例基底**正交且叠加取严**，
  不得以实例 sandbox 模式替代任务域授权，也不得反之。
- **拒绝项**：岗位级 ACL 覆盖文件系统路径（把组织规格绑死文件布局）；
  切实例 sandbox 为 read-only 来代任务域授权（帽子是任务域契约，不该动实例
  基底而导致并行任务误伤）。
- **实例身份注册表**（五字段代际绑定）＝capability 唯一绑定源，冻结语义照用；
  spawn env 白名单照旧，组织层不加每岗位 env 集。

### E. 工具面

- **复用宿主原生 `tools` 服务按岗位注册**，注册内容从岗位卡派生；**否决 MCP**
  （外部进程依赖与版本耦合踩宿主更迭义务）**与自建 bot 侧装载面**。
- **一 op 一工具、工具名即 op 名**（`task.claim`／`artifact.submit`／
  `evidence.probe`…），与 op-set 表一一映射——**工具面裁剪＝权限裁剪**。
  否决语域聚合工具（参数里藏 op 分派）。全员基础工具＝`mail.send`＋
  `knowledge.register|search`＋`ledger.read`。
- **复核帽的注册集本身不含写工具**（不是「注册了但拒绝」）。
- **简报与 capability 信封经接单响应携带，不进系统提示段**——简报是任务动态
  对象，注入多任务会串台；响应携带使「接单即得契约」原子成立。`amend` 经台账
  事件投影推送。
- **mail 收口 host 中继**：bot 侧底层改走认证命令 `mail.send`（对 bot 仍零
  capability 门槛、consult 语义不变），**bot 直写 inbox/outbox 取消**、host
  成唯一写者（消灭多写者与序号锁，闭共享面 writer ownership 缺口）。
- **knowledge 登记命令化**（认证命令，全员持有该 op）；检索与磁盘直读照旧
  （读面不收口）。
- **可执行检查（探针）接线**：探针工具挂 `evidence.probe` op；判据来源改为
  **台账四要素简报的验收预登记**（不再取任务工件正文——「模型不得自报判据」
  原则保留）。规格锁两条：①判据必须能表达为白名单内命令；②**白名单机制必须
  存在且 fail closed**。具体命令清单属实现轨道、可扩；沙箱快照与逐字一致校验
  形态照用。
- **失效三分支**（**无文件直写降级路径**）：通道不可用→错误回执＋有限重试，
  持续不可用→上抛；鉴权拒绝→错误回执＋台账拒绝事件；工具语义失败→正常进
  任务流程（报 gaps／修复回合）。
- **动态工具面不变量**：实例任一时刻可用的组织命令集＝**home 岗位 op 集 ∪
  当次被签发 capability 的 op 集**（帽卸或租约回收即失效，与吊销联动同拍）。
  实现取运行时动态注册或门控属实现轨道；走门控时复核帽的写 op 排除须工具层
  与 host 命令层**双层都不放行**。

### F. 人间接口

- **只有三类进 `waiting-user`**：不可逆写入的放行／上浮终裁（冲突、复核两轮
  未闭合、越权处置）／用户域裁定请求（模型指派、预算等）。其余到人事件
  （交付回笼、取消失败、越权计数）＝**纯告知，不挂起**。
- **投递面＝人间收件箱**（台账 `waiting-user` 与通知事件的直接投影，内嵌终裁
  操作）；mail＝可选出仓库只读转发，**回文永不构成裁定**。规格只定「投递面＝
  事件投影＋可裁定」的契约，前端实现形态归 UI polish（Out of scope）。
- **等待语义**：`waiting-user` **无超时自动动作**——挂起无限期，不占租约、
  不烧 token；提醒属投递面节律（数值用户域），不产生新台账事件语义。唯一
  例外类：简报边界声明的业务截止时间到期→台账投影「已过期」供用户清理，
  **仍不自动取消**。
- **验收初审代理边界**（值班统筹或指派的便宜模型实例佩戴，台账事件记录模型
  身份）：**可处置**未命中必审清单的产出（通过／回笼）；**只可整理**命中清单
  产出的裁定包；**强制上浮**于初审拒绝或判据两轮未闭合；**永不可代**三项——
  模型指派、越权处置、冲突仲裁。
- **终裁＝普通台账命令的特化视图**（`actor=user` 的接单/驳回/推迟/授权修复
  命令，继承幂等键、CAS 与事件审计），**不另起第四套命令面**；前端收件箱按钮
  即触发器。
- **裁定包五件**：冻结版四要素简报／触发上浮的判据事实（命中条目＋可执行检查
  结果原文）／双方立场各一句＋全轨迹指针／可选动作清单及各自后果／模型身份。
  不自动附全文工件，按指针取用。

### G. 记忆与知识层

- **三层定形**：岗位私有记忆＝实例 workspace 内自由笔记（唯一合法直写区，
  无 schema、无专用工具）；**团队共享不设独立第三面**——任务事实走台账、
  可复用结论走知识库；组织常量（岗位卡／评测集／例程登记项）＝配置面，
  不算运行时记忆。
- **岗位私有存续**：文件即记忆，DSH session 残留不作记忆依据（turn baseline
  纪律）；实例消亡则随 workspace 留存但**无备份/迁移义务**、岗位重建不保证
  继承（刻意低承诺，倒逼值钱结论走晋升）；他实例读取走既有直读面（合法但不
  承诺）。
- **写入分流三问**：①本任务历史事实→台账事件；②换一个不同任务仍成立→
  知识库；③中间产物→taskId 键工件存档（归档不删档）。**推理过程任何面都不进**。
- **晋升规则**：时点＝任务关闭或归档流程内；触发人＝产出方；强制性由派单方在
  简报输出格式里**预声明**（全局不设强制，「登记不构成任务完成依据」）；门槛
  三条——过换模型试金石、**可独立成立**（不读原任务轨迹即可用）、留痕
  （复用/取代登记照用）。**不设强制复核点**（保留可加审）；「该登没登」不机械
  追偿，靠复用率人工观测。
- **失效规则**：台账 append-only 永不失效；知识库唯一失效机制＝**显式取代/
  废弃登记**（append 语义、不物理删除、旧痕迹保留），**不做**自动失效、自动
  打分或访问热字段。冲突裁决：知识与台账冲突**台账胜**；知识与岗位卡冲突
  **岗位卡胜**；冲突条目须取代收口。
- **知识库在组织层件白名单的位置**：**容器协议**（登记/检索/取代语义、索引
  协议）进白名单；**条目内容不在白名单**＝运行时产出资产，逐条自负试金石。
- **移交与保留**：只传指针（任务 id＋工件坐标＋知识条目 id），不复制内容；
  接手方拉取式自取；工件**归档不删档、无保留期上限**。
- **检索引导**：「开工先 search」只写进调研承载岗的岗位卡派生提示段，不全员
  灌；检索面维持**索引级子串**（否决向量检索与全文检索）；复用率维持人工核对、
  不自动检测。

### H. 宿主适配面与探针

- **判定规则按失配后果分类，不按层**。操作判据一句：**「宿主把此面改名或改
  形状后，组织层会不报错但做错吗？」**
  - **A 类＝静默降级面**（会）：必须经**可替换适配层**（形状收敛到单一坐标，
    改名只动一处）＋挂**行为探针**（真实调用一次并断言结果形状）。成员：
    配置面 id/key、前端槽位与视觉件、`ctx.get` 取空跳过支与身份判定、会话
    日志面、**v2 台账落盘格式**（尚未落地）。
  - **B 类＝响亮失配面**（不会）：登记＋存在性/形状探针即可**直用**。成员：
    组织层身份面（插件名与 inject、client bundle 协议、inject 清单）、宿主
    RPC、spawn CLI 与 `DSH_HOME` 语义、台账命令面。
  - **C 类＝非宿主面**：OS 与语言契约（进程代际绑定、事件流、HTTP 标准）与
    本仓自有面（SSE 端点、mail/knowledge 文件服务）——**显式列出并标注排除
    理由**，防后人重新纳入。
- **宿主适配面登记表**为组织层件白名单第 6 类，切分照知识库先例：**容器协议
  （字段集＋登记纪律）进白名单**（逐条过试金石）；**条目内容＝运行时资产**，
  宿主更迭改条目、不改规格正文。字段集：面 id／宿主坐标／读取方式／类别／
  适配层归属模块／探针 id／失效表现／末次探针结果指针。岗位卡第 8 字段
  **引用面 id＋本岗敏感性说明，不重复坐标**。
- **版本探测仅作诊断字段、不作门**；**门只由行为断言把守**。
- **探针三态 PASS/FAIL/SKIP**：**SKIP 必须分列计数并向用户可见**（打印原因与
  探测坐标），汇总行形如 `N PASS / M FAIL / K SKIP`。仅「本机未安装该宿主」的
  开发机或 CI 场景允许 SKIP 且不阻断；**bot 运行面与部署面上 SKIP 视同 FAIL**。
  修掉现有存在性守卫在门汇总行上与真通过同形的假绿。
- **FAIL 分级（fail closed 但不全停）**：默认＝**面级降级**（该面相关 op 与
  工具不注册、通道关闭，其余能力照常，沿用工具面三分支口径）；**例外＝整层
  拒载，仅限组织层身份面**。失效可见可归因：探针失败或运行面跳过以
  **class=duty 例程任务**落台账承载处置（**不新增台账事件类型**）并按人间
  接口告知。A 类的存在理由就是消灭静默。
- **探针挂载点**：独立脚本作为 preflight **第 4 道门**（插在冻结面复验之后），
  **不并入测试套件**（测试入口无跳过通道、且既有纪律是不把套件耦合到宿主安装
  状态；而探针必须知道宿主在不在）。分工：探针管「宿主面在不在、形状对不对」
  （跨版本、可跳过）；既有行为断言管「仍在时的行为对不对」——互补不替代。
- **责任归属**：适配层与探针**代码**＝实施者；**巡检编排与升级评测编排**＝
  值班统筹；**宿主版本处置**＝人间面。组织层唯一自足的回退＝回退到「已探明
  面」的降级形态；宿主版本回退不属组织层权限。**红线：不得把回退实现为
  「取消适配层、直接读宿主私有面」**。
- **前端**：只准依赖宿主**显式注册面**（槽注册与 inject、公开布局动作、本地化
  面、UI 原语导出、client inject 声明）；**禁读宿主私有 DOM 结构与样式钩子**。
  公开 API 可直用但登记为 A 类面（槽位让位是静默的）。已知越界 1 处登记在案，
  代码处置见 §I。「兜底」的验收＝槽装载探针＋一次人工目视功能清单，**不设
  视觉回归**；宿主 UI 大改不构成「重做前端」义务。

### I. 重建、迁移与切换

- **一批式切换、不设双轨期**，分三段：
  - **前置段（仓库侧）**：v2 组织层件落地（岗位卡／协议／台账／权限／工具／
    人间接口／记忆／宿主适配）＋§H 的四项代码改造＋下列迁移工作清单。

### J. 恒久性与模型更迭

- **分界规则**：**组织层件白名单封闭枚举**（协作协议、任务台账、复核件套、
  权限四层、岗位卡第 1–6/8 字段、知识库容器协议、宿主适配面登记表容器协议），
  逐条受**换模型试金石**约束（「换一个更强模型，这条会变成废话或障碍吗」——
  会即出格、降级为岗位细节）；**白名单外任何文本默认＝岗位细节**。岗位细节
  只许住三处：岗位卡第 7 字段（模型档位，用户域留空）、提示段（岗位卡派生
  物）、实例配置（模型指派）。升级例程删指令时**只允许动这三处**。
- **恒久判据 D1–D11**（组织层件内逐条有对应表述；机读形态＝
  `lib/org/durability.js` 的 `DURABILITY_CRITERIA`，下列表述与它**逐字一致**，
  12 号票落档）：
  - D1＝上下文预算分层：每岗位显式定义预算与分层（常驻最小集＋按需检索标识符＋外置记忆），预算按有效上下文计。
  - D2＝稳定前缀：提示段与工具表用稳定前缀＋append-only 演进，改岗位细节不改结构。
  - D3＝移交契约：跨岗位移交走四要素契约（目标／输出格式／来源约束／边界），裁剪须显式声明。
  - D4＝并行条件：默认单线程线性；仅当子任务上下文真正独立时并行，且并行方只产信息、不可逆动作收归单线程。
  - D5＝可执行规程资产：规程落知识库与探针白名单两形态，文本化、可执行、不进提示咒语。
    覆写出处＝07 号票工具面裁定（原「可执行技能库」口径改写为知识库＋探针白名单两形态，v2 词表无该旧概念）。
  - D6＝团队共享上下文：共享走台账与知识库两面，不设第三面、不进模型私有通道。
  - D7＝验证外置：每岗位产出配可执行检查，复核用 fresh context 只看 diff＋判据、报 gaps 不报 style。
  - D8＝工具面是岗位卡派生物、跨模型稳定、工具名与 op 名模型无关。
    覆写出处＝07 号票工具面裁定（原「工具接入走 MCP 类标准协议」改写，MCP 字样移出规格判据）。
  - D9＝升级做减法：模型更迭触发岗位评测，预期动作是删指令；删不掉的约束才沉淀，沉淀物须模型无关。
  - D10＝复杂度递增：单岗位能解就不加协调层；加层唯一理由是上下文隔离或并行收益，token 成本为显式代价。
  - D11＝无岗位以 danger-full-access 为履约前提（06 号票追加）：全部岗位在 workspace-write 下可履约。
  被覆写的 D5／D8 已在上列各自表述内注明覆写出处（07 号票）。
- **模型更迭升级例程四步**：①触发——用户改实例模型指派落注册表 → 台账
  **自动登记** class=duty 评测任务（不依赖用户记得手动跑）；②执行——受影响
  岗位实例在**新模型下**跑岗位评测集；③**做减法**——评测通过且质量不降则删
  提示段规定性指令，删不掉的约束沉淀进知识库（沉淀物过试金石）；④验证与
  终裁——评测结论按复核件套投递用户，用户终裁是否收编新指派，评测不过则回滚
  指派为默认建议。
- **岗位评测集**＝组织常量，按岗位卡「输入输出契约＋验收判据」派生；每岗位
  **1–3 个冻结样本任务**（契约回放），判据可执行、样本本身过试金石（不得依赖
  特定模型输出风格）；**存量抽验不进规格**。规格只要求「每岗位至少一个可执行
  评测项」，规模与频次数值属用户域。
- **价值表述**（可验证）：「对给定模型组合 M 与任务集 T：若 M 中任一**裸实例**
  （单实例、无组织层脚手架、同权限面、**同基础工具面、无组织命令**）在预算 B
  内无法以合格判据完成 T，而 v2 组织形式（同一 M、同预算量级）能完成，则组织
  形式在 M 上提供独立于模型智能的价值。」裸＝去组织层不去基础工具面；预算量级
  同阶即可；判据沿用简报的可执行验收，不另造评委。
- **放大验证实验设计**：任务集＝3–5 个按放大机制各取一；对照＝上述裸实例；
  机制归因＝事后从台账事件投影出场清单（分解／互检／外置／并行），**不做
  对照组消融**；频次＝一次性规格验收实验，例行只保留换模型岗位评测，不设周期
  性基准。

## Testing Decisions

### 什么算好测试

- **只测外部行为**：判据看可观测产出与事件序列，不看实现细节。每条判据三字段
  ——判据文本／**执行坐标**（测试模块名、门号、台账查询语句或探针脚本）／
  **证据落点**（增量包字段或台账事件）。
- **「过」只三类**：可执行判据看断言与退出码；台账投影判据看查询是否返回预期
  事件序列；**人工判据只允许两类白名单**——前端目视功能清单与知识复用率人工
  核对，且须列明核验人。白名单外的「人工确认」按**判据缺口**处理，先分解为
  可观测项，分解不出来标 `needs-user` 上浮。
- **判定只有两态、fail closed**：A 组任一条红即不通过，无「部分通过」；B 组按
  预登记门槛判。不通过**不自动回滚**，走修复再复跑，连续两轮未闭合上浮用户
  终裁；结论与失败证据一并落档，**不做事后判据调整**。
- **依赖研究前提的条目只核「按设计实现」**（实现与规格一致、机制在实验中
  出场），**不核研究前提成立**。挂标终态照 16 号票裁定：研究依据已一手核验的
  条目转正常条目；矩阵前提相关条目挂「**设计推理（无直接文献）**」标注并
  **保留单列计数**（防用验收为推理前提背书，也防跳过式假绿）。
- **数值门槛属用户域**：绝对预算 B、量级倍数、重派封顶、初审与越权阈值由用户
  在实验前填进预登记件并随即冻结；规格只留「必须有这些可配置缝」的形状要求。
  任务集、对照口径、成本口径同样实验前登记、跑完不得改。

### 测哪些模块

- **台账**：状态投影与重建、非法转移与 CAS 拒绝、租约回收与重派封顶、
  `waiting-user` 不占租约不烧 token、关闭不可重开、例程幂等。
- **权限与 capability**：四层各自可检验、台账命令三元组各有负例、op-set 表与
  实际签发对账、复核帽无写通道、禁用直写面、危险模式不作为履约前提、拒绝
  fail closed 且留台账事件、邮件零权威。
- **工具面**：按岗位卡派生注册、一 op 一工具与 op-set 逐项一致、构建期漂移
  校验失败、简报不进系统提示段、mail 无直写路径、知识登记命令化、探针白名单
  fail closed 与逐字一致校验、失效三分支、复核帽注册集不含写工具。
- **复核件套**：必审清单命中即阻断、清单外咨询性、判据预登记与不可执行即缺口、
  复核只读、两轮未闭合上浮、产出方不得自任。
- **岗位集与岗位卡**：五类角色类别各有卡、八字段齐备、放大机制非空、slug 稳定
  性、无常驻复核席位、借用期 op 集不变量。
- **记忆与知识**：写入三问分流、晋升三门槛、失效唯一机制、冲突裁决优先级、
  移交只传指针、归档不删档。
- **恒久性**：白名单封闭枚举齐备、岗位细节只住三处、组织层件内无模型特定假设
  （可由扫描检查）、D1–D11 逐条有对应表述、升级例程四步可执行。
- **人间接口**：三类裁定进 `waiting-user`、其余纯告知、无超时自动动作、初审
  代理边界、终裁即台账命令、裁定包五件齐备。
- **宿主适配面**：登记表字段集齐备、A 类经适配层、探针三态与跳过分列计数、
  运行面跳过视同失败、门只由行为断言把守、宿主契约门在位、失败面级降级、
  失效落例程任务、前端只依赖显式注册面。

### 测试接缝

只用既有接缝，不新起平行体系。**最高接缝＝preflight 的单一 fail-closed 出口**
（三道门 AND 成一个布尔、退出码即结论）：

1. **测试套件接缝（既有）**：回归入口逐文件派生子进程执行，任一失败即非零
   退出。A 组的「常驻」判据落成测试模块，**测试名本身即执行坐标**——不另立
   机器可读清单文件（多一份清单就多一个会漂移的事实源）。文件头既有纪律
   「禁止改用目录形式跑测试」照旧。
2. **门接缝（既有＋新增一道）**：全量回归门／冻结面校验门／状态词表门，加
   **宿主契约门**（新增，挂在冻结面门之后，独立脚本、不并入测试套件）。四道门
   AND 成一个布尔。
3. **受控执行接缝（既有）**：沙箱探针（一次性物化副本＋命令白名单＋逐字一致
   校验）作为所有岗位「可执行检查」的共同底座，也用于任务内验收判据的机器
   判定。
4. **台账投影接缝（新建，但已由任务台账决议定型）**：需要活台账或活实例的
   判据按台账查询语句判「事件序列是否符合预期」。
5. **人工目视接缝（白名单内）**：前端功能清单一次，列明核验人。

**A 组覆盖级别两级**：**常驻**＝进测试套件或门、随每批回归执行，对象是不依赖
运行面的结构判据；**实验期一次**＝在切换批 smoke 与验收实验期内执行并留证，
对象是需要活台账或活实例的判据（台账状态与租约类、capability 签发吊销类、
收件箱类）。默认实验期一次的具体条目见附录 A 标注；其余默认常驻。成文时若某条
经复核判定须改级，按显式修订走并记理由。

**坐标齐备度**：规格底稿允许标「坐标待实现批补齐」；判据语义在定稿时冻结、
落地坐标在实现批补齐，两件事分开管。**切换批的前置判据含「A 组坐标无空缺」**。

### 执行编排

- **A 组**随 v2 实现批执行（四道门＋全量回归＋新增验收测试模块）：实施者执行，
  证据进增量包，**复核帽独立核验**判据坐标可核与产出一致性；窗口＝切换段完成、
  双席就绪探针通过之后。
- **B 组**＝切换批最小闭环 smoke 通过后的**一次性实验**，由值班统筹编排；
  裸对照与组织内跑分用不同实例，产出方不得自任复核者；结论按人间接口口径投递
  用户终裁。
- **落档三处**：判据执行记录与实验原始数据进**证据包链增量包**（新 runId 重
  采集、出新序号包，永不覆盖既有终版包）；结论摘要进 `CHANGELOG.md` 顶部条目；
  可执行判据的通过记录**进台账**。**不新建状态类文档**；需要人读验收报告时按
  一次性件出一份并同步 README 文档地图。

## Out of Scope

- **UI polish**：前端实现形态（视觉、布局细节）不入本规格；本规格只定前端
  适配边界（只依赖宿主显式注册面、禁读私有 DOM 与样式钩子、槽装载探针＋一次
  人工目视、不设视觉回归）。
- **阶段 3/4 基建债**：存储统一与模块拆分、可观测与执行隔离——留既有轨道
  （单向边界指针见 Further Notes）。
- **模型选型与 token 预算数值**：具体模型指派与预算数值属用户裁定域；本规格
  只保证岗位-模型解耦、指派可配置可更换、用量可观测的缝。
- **v2 切换部署的执行**：部署同步与重启链是出仓库动作，受逐项点名约束，另起
  部署批执行；本规格只定切换形态与切换点判据。
- **历史件改写**：旧评审形态的代码删除归实现批（见 Implementation Decisions
  §I），但 PLAN 冻结决策表、证据包链、既有冻结文档**不重写**（加废止标注或
  保留原样）。
- **研究前提本身的成立性**：本规格验收**不核**研究前提是否成立，只核实现与
  规格一致、机制在实验中出场（附录 A 对矩阵前提相关条目挂「设计推理（无直接
  文献）」标注并单列计数）。
- **研究面**：v2 不再预留「补充调研轮」；未来新研究问题按 wayfinder 惯例开新票。

  错位」类失败**不充分**，故复核件套的触发权依据只挂到「验证与协调类」失败
  上；「可预防」表述已收窄。

  同一批实例」属推理，相关验收条目挂标注并单列计数。

### 单列计数：挂「设计推理（无直接文献）」标注的条目

矩阵前提相关条目（值守线与项目线共享同一批实例的映射）挂此标注并单列计数，
与常驻/实验期一次的覆盖级别标注**并行记录**，二者不互替。挂标机制的目的仍
成立——防用验收为推理前提背书，也防跳过式假绿。

**挂标条目（1 条）**：`V-A1.4`——「一实例一 home 岗位、可被项目线借用；
借用期可用组织命令集＝home op ∪ 当次签发 op」。该条目断言的是**同一实例池
在不同时段配成不同单线结构**（03 号票「值守线／项目线共享同一批实例」映射），
而矩阵直接文献不存在（16 号票裁定：OrgAgent §3.1 限定只研究扁平与层级两种
形态，相邻证据仅支撑同池异时复用）。其余条目（含 `V-A2.6`「一实例同时只持
一个进行中任务」）断言的是**组织级不变量**（单一时刻单一任务归属），由 03 号票
独立裁定、不依赖矩阵推理，故不挂标。

**计数基线**：本规格定稿时挂标条目数＝**1**，于 `CHANGELOG.md` 冻结条目中
记录；实现批与执行批**只补坐标、不改计数**；计数变化须走显式修订。
