## Answer

**岗位集＝4 个职能角色类别＋1 个按需复核角色类别**。角色类别（role class）＝契约
单位，实例按需存在；bot 是载体，一个实例有一个 home 岗位、可被项目线短期借用。
每岗按岗位卡八字段定义（一句话职责／触发条件／输入输出契约／边界〔不做什么〕／
存在理由／放大机制〔必填，填不出＝只摊成本不设岗〕／模型档位〔用户域，留空〕／
依赖面·更迭敏感性）。

| 岗位（slug） | 一句话职责 | 触发条件 | 存在理由（终景需求） | 放大机制 |
|---|---|---|---|---|
| 值班统筹 `duty-coordinator` | 接单与分诊：接收用户目标与外部事件，判定走确定性路径或上浮；维护组织常量（知识索引／规程文本／席位健康）；代表组织投递裁定请求 | 常驻可用（LLM 部分按上浮唤醒） | 常态值守＋人间接口归一＋组织常量 | 外置（规程/知识工件化）＋流程脚手架 |
| 项目经理 `project-lead` | 目标态统筹：立项判定、分解、四要素简报、按 scaling rules 控动员规模、跟踪与结算、产出回笼 | 目标到达且分诊判定需编组 | 目标→团队自治 | 分解＋并行（上下文隔离） |
| 研究员 `researcher` | 事实调查：对指定问题取得可引用的事实与来源，产报告（含盲区清单） | 项目经理派单 | 超单窗信息／外部知识面 | 外置（工件）＋隔离（独立上下文） |
| 实施者 `implementer` | 实施：按简报改工件（代码/文档/配置）、跑可执行检查、出证据；含宿主适配层维护 | 项目经理派单 | 需要动工件的执行 | 互检（验证外置）＋外置（证据） |
| 复核者 `verifier` | 独立复核：只看 diff＋判据，报 gaps 不报 style | 关键产出的复核点（形式归 04） | MAST「任务验证缺失」类失败 | 互检（fresh context） |

复核者是**第 5 个角色类别**：有岗位卡、有独立只读权限面与独立上下文预算，但
**无常驻席位**，实例按需召集——「评审不成岗」指不入常驻编制（Q5B），非无契约。

**不单设岗**（职责归属及判据）：

1. 分诊／验收初审 → 值班统筹（判断部分）＋确定性组件（机械部分）。初审作为流程
   步骤的承载者可选复核者实例或值班统筹，形式归 04/05。
2. 知识维护／规程维护 → 值班统筹职责＋每岗「谁产出谁登记」。合并判据②：共享同一
   上下文与工具面；单列会产生自检自（自己维护的规程审自己）。
3. 调度／派单 → 常态归值班统筹、目标态归项目经理（Q3C 两顶帽子）。
4. 模型升级评测 → 值班统筹组织的例行职责（升级例程 D9；细节归 08）。
5. 设计 → 并入实施者（同一上下文预算内的设计-实现闭环）。

**组织级不变量**（细节归 05）：

- **单一时刻单一任务归属**：一个实例同一时刻只属于值守线或项目线之一，归属必须显式。
- **冲突上抛用户**：两线目标冲突时上抛用户，不在实例内自行取舍。
- **确定性优先**：机械动作归确定性组件；只有语义判断上浮给 LLM 岗，每次上浮必须可
  归因（为什么确定性判不了）。
- **单入口收单＋结论直通**：裁定请求归一入口；产出报告/工件原文直达用户，不做改写
  转述。
- **验证外置与复核隔离**：每岗产出配可执行检查；独立复核以 fresh-context 实例进行，
  只看 diff＋判据、只报 gaps 不报 style。

**命名**：英文 slug 为契约主键（`duty-coordinator` 等），中文名为显示名；工具/权限
命名空间按 slug 前缀（细节归 06/07）；改显示名不动契约（D2 稳定前缀）。

**现役四席：无保留义务，直接按 v2 重建**（2026-09-10 用户裁定：「完全无所谓，没有留
的必要，直接重建」）。lead／研究员／reviewer-lead／reviewer-second 不构成 v2 编制
基线；提示层 `lib/index.js:2394-2416`（双审军规＋双审试点门控）与双席 stage 协议属
旧形态，随重建收口（协议存废归 04/05）。宿主实现约束（lead 条目代码内置、不可删除
`lib/index.js:1064`；注册表空时自动重建）在重建时须处理——属实现约束，不构成编制
义务。

**宿主面更迭义务**（用户本轮追加约束的落地）：

- 组织规格不得依赖会被 DSH 更新代换的内部面（cordis 槽名／client bundle 结构／
  host HTTP API 形状／模型解析链）；宿主依赖须显式隔离为可替换适配层。
- 岗位卡第 8 字段「依赖面／更迭敏感性」承载此义务。
- 前端「与 DSH 原生像素级统一」期望**降级为「原生一致优先、功能可用兜底」**；UI
  形态不入本规格（Out of scope 维持）。
- 专票 11「宿主/插件面更迭的隔离与升级」承接规程与验证（Blocked by: 03, 08）。

**证据与限制**：

- 值守线＋项目线共享实例的**矩阵前提缺直接文献**（01 号报告盲区 1，OrgAgent 不可达）
  → 该映射属推理，按 map 网络声明标 **待补充轮复核**。
- 设计依据：01 号报告 §2/§6（模式菜单、按岗配档、规模红线）＋ §5；02 号报告 §5
  D1–D10、§4 反例 R1–R10。两份报告均为网络受限下的**暂定稿**。
- 事实底稿（只读调查）：今天**无任何常驻值守岗位**（分诊/验收初审/知识维护/调度
  检索零命中），实施面**成员空缺**（PLAN-expanded-engineering.md:84「编码方实例：
  未创建」）——故 5 类岗位均为**新建/重建**，非迁移。
- 能力放大向检验：五个岗位各自填出放大机制（互检／隔离＋外置／证据外置／分解＋并行／
  流程脚手架）；**全低配压力测试**仍为规格验收候选（雾区，待任务生命周期定型）。
