# 人间接口规格

Type: grilling
Status: resolved
Blocked by: 05

## Question

用户关键裁定的投递面：哪些裁定必须到人（模型指派/放行/争议仲裁）、投递
形式（邮件/通知/SSE）、等待与超时语义（人不在场时组织怎么办——挂起、
降级还是绕行）、便宜模型代验收初审的边界（审什么、什么必须上浮）。

## 来自 04 号票的输入（2026-09-10 裁定）

- user-decision 存储（`lib/review-results.js:44-65`：accept/reject/defer/
  authorize-repair、作者必须为 user、principal 来自本地 CSRF token、单调 revision
  ＋幂等重放）**升格为 v2「人间终裁」原语**——投递面由本票细化。
- 复核形式已定（04）：必审产出阻断性交付、连续两轮未闭合上浮用户终裁；本票定该
  上浮的投递形式与等待／超时语义（人不在场时组织怎么办）。

## 来自 05 号票的输入（2026-09-11 裁定）

- **挂起语义**：等待用户裁定＝`waiting-user` 持久挂起，**不占实例租约、不烧
  token**（05 Answer §7③）——本票定该状态如何到人、等待与超时（人不在场时组织
  怎么办）。
- **通知事件面**（05 §10，形式归本票）：到用户＝交付/回笼、上浮（两轮未闭合／
  冲突／重派封顶）、`waiting-user` 裁定请求、取消/失败。通知必须是台账事件的
  投影——**无事件不通知**。
- **终裁原语**：user-decision 升格为 v2 人间终裁（04 Q7）——05 只声明上浮触发，
  投递与终裁界面归本票。

## 来自 06 号票的输入（2026-09-12 裁定）

- **user principal＝台账全权**（可发一切台账命令，不经岗位 op 表；06 §10）——
  本票的人间终裁界面与该全权的衔接：终裁是 user 命令的特化投递面，不是另一
  套权利定义。审计线：user 命令与 bot 命令同走台账事件（actor=user）。
- **越权/拒绝通知**：命令被拒＝台账事件＋错误回执；连续越权→通知派单方并
  计入上浮（阈值数值属用户域）（06 §6）——到人/到岗的形式与等待语义归本票。

## Answer

2026-09-12 用户裁定：round 1 六问全裁「无异议」＝按推荐授权定案。

### §1 必须到人的裁定清单（Q1）

只有**三类**进 `waiting-user`：①不可逆写入的放行；②上浮终裁（冲突／复核
两轮未闭合／越权处置）；③用户域裁定请求（模型指派、预算等——CONTEXT.md
已定用户域事项）。其余到用户事件（交付/回笼、取消/失败、越权计数）＝**纯
告知**，组织继续走、不挂起。任务验收终裁**不默认等人**——走 §4 初审代理
＋例外上浮，终裁仅在初审拒绝或判据两轮未闭合时发生。

### §2 投递形式（Q2）

**单一权威投递面＝DSH 前端的人间收件箱**＝台账 `waiting-user`／通知事件的
直接投影，内嵌 user-decision 裁定操作。mail＝**可选出仓库转发**：同内容只读
副本；裁定必须回前端／命令面做，**mail 回文永不构成裁定**（与「零权威通道」
一致）。SSE 是前端传输层，不算独立通道。规格只定「投递面＝事件投影＋可
裁定」的契约；前端实现形态按既定 Out of scope「UI polish」处理。

### §3 等待与超时语义（Q3）

`waiting-user` **无超时自动动作**——人间裁定不可被组织单方面代裁、降级或
放弃，挂起无限期。提醒＝投递面节律问题（重复投影，节律数值用户域），不产生
新台账事件语义。挂起不占租约（05 §7③），无租约池封顶问题。唯一例外类：
简报 `boundaries` 声明的业务 deadline 到期→台账投影「已过期」状态供用户
清理，**仍不自动取消**。

### §4 验收初审代理的边界（Q4）

采用「B 的收窄版」：初审代理（值班统筹或指派的便宜模型实例佩戴，台账事件
记录模型身份）——

- **可处置**：未命中必审清单的产出，做出「通过／回笼」处置并留台账事件；
- **只可整理**：命中必审清单（不可逆／对外可见／跨实例关键）的产出，初审
  只产出**裁定包**（§6），处置权永远在人；
- **强制上浮**：初审拒绝，或判据两轮未闭合；
- **永不可代**（三项）：模型指派、越权处置、冲突仲裁。

### §5 终裁界面与台账命令的衔接（Q5）

终裁＝**普通台账命令的特化视图**，不另起第四套命令面：user-decision 的
accept／reject／defer／authorize-repair 各自是 `actor=user` 的台账命令
（继承幂等键＋CAS＋事件审计，06 §10 user principal＝台账全权），「终裁」
只是这些命令在 `waiting-user` 语境下的命名；前端收件箱按钮即触发器。
authorize-repair 语义随 v2 复核件套复核：授权＝允许产出方进入修复回合。

### §6 裁定包最小内容（Q6）

裁定包五件（对齐恒久原则 D3「最小充分指令」）：①任务四要素简报（冻结版）；
②触发上浮的判据事实（命中条目＋可执行检查结果原文）；③产出方与复核/初审方
各自立场一句话＋taskId 全轨迹指针；④可选动作清单（accept/reject/defer/
authorize-repair 各自后果一行）；⑤模型身份记录。不自动附全文工件——按
指针 zoom。
