# 人间接口规格

Type: grilling
Blocked by: 05

## Question

用户关键裁定的投递面：哪些裁定必须到人（模型指派/放行/争议仲裁）、投递
形式（邮件/通知/SSE）、等待与超时语义（人不在场时组织怎么办——挂起、
降级还是绕行）、便宜模型代验收初审的边界（审什么、什么必须上浮）。

## 来自 04 号票的输入（2026-09-10 裁定）

- user-decision 存储（`lib/review-results.js:44-65`：accept/reject/defer/
  authorize-repair、作者必须为 user、principal 来自本地 CSRF token、单调 revision
  ＋幂等重放）**升格为 v2「人间终裁」原语**——投递面由本票细化。
- 复核形式已定（04）：必审产出阻断性交付、连续两轮未闭合上浮用户终裁；本票定该
  上浮的投递形式与等待／超时语义（人不在场时组织怎么办）。

## 来自 05 号票的输入（2026-09-11 裁定）

- **挂起语义**：等待用户裁定＝`waiting-user` 持久挂起，**不占实例租约、不烧
  token**（05 Answer §7③）——本票定该状态如何到人、等待与超时（人不在场时组织
  怎么办）。
- **通知事件面**（05 §10，形式归本票）：到用户＝交付/回笼、上浮（两轮未闭合／
  冲突／重派封顶）、`waiting-user` 裁定请求、取消/失败。通知必须是台账事件的
  投影——**无事件不通知**。
- **终裁原语**：user-decision 升格为 v2 人间终裁（04 Q7）——05 只声明上浮触发，
  投递与终裁界面归本票。

## 来自 06 号票的输入（2026-09-12 裁定）

- **user principal＝台账全权**（可发一切台账命令，不经岗位 op 表；06 §10）——
  本票的人间终裁界面与该全权的衔接：终裁是 user 命令的特化投递面，不是另一
  套权利定义。审计线：user 命令与 bot 命令同走台账事件（actor=user）。
- **越权/拒绝通知**：命令被拒＝台账事件＋错误回执；连续越权→通知派单方并
  计入上浮（阈值数值属用户域）（06 §6）——到人/到岗的形式与等待语义归本票。
