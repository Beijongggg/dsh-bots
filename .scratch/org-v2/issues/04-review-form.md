## Answer

**2026-09-10 grilling round 1 用户逐项裁定（Q1=3／Q2=3／Q3=1／Q4=3／Q5=1／
Q6=按推荐／Q7=按推荐／Q8=按推荐）——「评审」在 v2 中的存在形式＝
「必审清单＋判据＋gaps 报告＋修复回合＋上浮」一件套。**

### 1. 触发权（Q1=③ 双轨，裁量方向限死）

- **必审清单**（命中即强制复核，无人可豁免）三条判据：**不可逆**（写入真实
  运行面／冻结面）、**对外可见**（交付用户、跨组织提交）、**跨实例移交的
  关键产出**。
- 清单外默认走产出岗自证的可执行检查；项目经理可**加审**（须留归因），
  不可**免审**。确定性优先，不留豁免后门（对齐 03 Q2 判断上浮可归因）。
- 研究性依据（MAST「任务验证缺失」为主要可预防失败类别）出自 01 号报告
  （网络受限**暂定稿**）→ 此点标注 **待补充轮复核**。

### 2. 处置权（Q2=③ 分级＋循环封顶）

- 命中必审清单的产出＝**阻断性**（gaps 未闭合不得交付／回笼）；清单外＝
  **咨询性**（复核者报 gaps，处置权在项目经理／用户）。
- 修复走**一次性修复回合**；**连续两轮未闭合即上浮用户终裁**（防死循环，
  终裁权留人，对齐 map Notes「终裁留用户」）。
- 复核者权限面**只读**，不得自行改工件（延续 03「只报 gaps 不报 style」）。

### 3. 判据与复核者能动性（Q3=① 判据预登记）

- 判据由**派单方在四要素简报中预登记，且必须可执行**；复核者只对照判据、
  并另报**判据本身的缺口**。
- 复核者**可自跑可执行检查**（复用 runProbe 沙箱探针：bwrap 隔离／命令白名单
  `node,git,grep,sha256sum,wc`／exit code 判据，`lib/review-evidence.js:414-505`）；
  **不得改工件、不得放宽判据、不得自行改口径**。
- 报告形状固定为「**gaps 列表＋严重度＋证据坐标**」（机械细节，用户未反对即
  按此入规格）。
- 与派单纪律 #17 的关系：该条禁止预置**产出方的语义决定**（reused/supersedes/
  tags），其首句明文将「验收标准」列为任务本身内容——给判据不违规。

### 4. 「独立」的可检验定义（Q4=③）

- 独立＝复核者**读不到产出方的推理轨迹与中间过程**，只拿到 diff＋判据＋工件
  本体。
- **fresh context 为硬要求**；模型同异**不设硬约束**（CONTEXT.md「模型指派」
  已定属用户域），但复核报告**须记录模型身份**，供趋同率度量（承接旧试水轮
  「异模型降级版」口径，`docs/PROJECT_UNDERSTANDING.md:200-204`）。

### 5. 复核者实例来源（Q5=① 帽子模型）

- 「复核者」是**契约帽子**：任意当次空闲实例可佩戴，**fresh 会话**，与被核
  产出无归属关系（与 project-lead「从常驻岗挑人任」同构，对齐 03 Q1 岗位／
  编制分离）。
- **硬约束：同一任务内产出方不得自任复核者**（自检自禁令）。
- **不设** verifier home 岗位专实例、**不新起**常驻编制；注册表外临时新建进程
  实例（须重走 spawn env 白名单／代际绑定链）留作「复核质量不稳定」时的后手。

### 6. 旧流程件：形态废弃（Q6=按推荐）

随 v2 规格生效**注销形态**：13 stage 协议与确定性 stage 机、双席席位
（reviewer-lead 3103／reviewer-second 3104）、提示层双审注入
（`lib/index.js:2394-2416` 军规＋试点门控）、review-enforcement 矩阵
（全 pending 无机械执行）、双审试水轮待触发项、规程 R-2026-007。

- v2 不复刻 stage 机：**转换权威不再来自确定性 stage 投影**，改为「必审清单
  命中→复核→gaps→修复回合→上浮」的极简件套。
- 13 stage 的**代码层处置**（PLAN P0.3 冻结逐字表 ＋ `lib/review-protocol.js`）
  属实现面，归 **12 号票**；本票只裁形态去留。

### 7. 可复用原语：保留并归位（Q7=按推荐）

| 原语 | 判定 | 归位 |
|---|---|---|
| review store 数据面（事件溯源／单写者锁／epoch fencing；GROK §5.5 判为强一致基座） | **保数据**（历史只读归档，新形态不继承流程件，复用其文件语义） | 12（并存与回退面） |
| capability 机制（`lib/review-capability.js`：HMAC 单次、绑定实例的通用权限原语，覆盖面含 job/evidence/artifact） | **保留为通用权限原语** | **06** |
| user-decision 存储（`lib/review-results.js:44-65`：accept/reject/defer/authorize-repair、作者必须为 user、principal 来自本地 CSRF token、单调 revision＋幂等重放） | **升格为 v2「人间终裁」原语** | **09**（投递面细化） |
| runProbe 沙箱探针（exit code 判据） | **保为所有岗位「可执行检查」的共同底座** | **07**（工具装载） |

### 8. 边界（Q8=按推荐）

- **04（本票）**：形式与权利——必审清单、阻断力、判据来源、报告形状、独立性
  定义、实例来源、旧件去留。
- **05**：位置与顺序——复核点在任务生命周期的哪个节点、超时／挂起语义、与
  派单／结算／关闭归档的耦合。
- **09**：投递——裁定如何到人、等待与超时、初审与终裁的界面。
- 必审清单的**具体条目枚举**若需随生命周期定型而细化，在 05 定义复核点时
  落地；本票已固定三条判据作为枚举依据。

**证据与限制**：触发权与阻断力的研究性依据（MAST 类失败可预防性）出自 01 号
暂定稿，标注待补充轮复核；其余依据为只读代码调查（本票 Comments 前置事实）
与本地 GROK 对比报告 §4/§5.5/§7/§10，不依赖网络。
