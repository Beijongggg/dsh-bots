# v2 规格验收标准

Type: grilling
Blocked by: 05, 08

## Question

v2「完整系统」的可观测验收判据：如何判定《团队组织形式 v2》规格被完整实现、
且组织形式确实提供价值（能力放大）而非只摊成本。原雾区条目「规格验收标准」
（候选含**全低配压力测试**——同批低配模型在组织内完成裸模型完不成的任务）
在 05 号票定形任务生命周期后毕业成本票。要定：

1. **验收判据清单**：规格实现完备性（岗位集／协议与生命周期／权限／工具／
   人间接口）与规格正确性（能力放大向检验）分开登记，每条判据可观测、可执行。
2. **全低配压力测试设计**：任务基准（固定任务集？历史任务回放？）、对照口径
   （同一模型的裸跑 vs 组织内跑）、放大机制归因（分解／互检／工件外置／流程
   脚手架各自贡献如何分离）、成本口径（token／墙钟／轮次）。
3. **判据预登记与不事后补判据**（方法论 #2）：验收判据何时冻结、执行窗口、
   谁执行、结果落档位置。
4. **与 08 的分工**：08 定组织恒久性判据与放大验证设计；本票在其上收口整卷
   规格验收，**引用 08 不重审**。

依赖说明：任务生命周期已由 05 定形（本票由此毕业）；"能力放大"向以 08 的验证
设计为输入；其余设计票（06/07/09）定型后本票收口；不产出代码。

## 来自 05 号票的输入（2026-09-11 裁定）

- 生命周期主干与状态集已定（05 Answer §9：`intake→…→closed` ＋四旁路）；
  任务对象／四要素简报／边界事件式复核点／关闭归档形态已定（§1–§8、§12）
  ——验收判据可据此写"逐状态可观测"。
- 建议验收面（待本票裁定）：每个状态有事件投影可查；必审清单拦截有效
  （gaps 未闭合不得 `delivered`）；`waiting-user` 不占租约、不烧 token 且可
  恢复；关闭后不可重开且事件链保留；一实例同时只持一个进行中任务。
- 「全低配压力测试」为 03 号票留下的规格验收候选；本票给基准与对照口径，
  归因口径以 08 的放大验证设计为输入。
- 研究依赖：01/02 报告为网络受限**暂定稿**，本票涉及的研究性结论按 04 口径标
  **待补充轮复核**。

## 来自 06 号票的输入（2026-09-12 裁定）

- **权限面验收候选**（06 已定形、可写成可观测判据）：四层各层可检验——共享
  面 bot 零直写（L1）、组织命令经认证 host 通道（L2 语义线）、op-set 表与
  实际签发对账（L2）、复核帽无写通道且无 `ledger.read`（独立性机械成立）；
  「无岗位以 danger-full-access 为履约前提」入验收（引用 08 判据，06 §8）。

## 来自 10 号票的输入（2026-09-16 裁定）

- **复用率 KPI**：知识复用率观测维持**人工核对、不自动检测**——作为规格
  验收标准的输入项（非自动化验收判据）。两个观测点照 v1 口径：任务启动时
  先查索引（过程）＋产出中引用历史结论（结果）。

## 来自 12 号票的输入（2026-09-16 裁定）

- **起步编制口径**：v2 落地起步＝**双席**（`duty-coordinator`＋`implementer`）；
  最小闭环判据＝「收单→派单→实施→复核帽→结算」＋台账事件投影可核。验收
  实验所需编制**按需扩编**，不抬升起步编制（12 Answer §3）。
- **可用验收面**：切换批本身提供一次**最小闭环 smoke**（真任务走完全链），
  可作规格实现完备性的第一道野外样本；门面判据＝`preflight` **四道门**
  （含 11 号票待建第 4 道 `host-contract`）＋编制就绪探针（12 Answer §1／§9）。
- **不可用作判据的面**：mail 面随 12 号票**保数据不保形态**（废 `kind` 与
  `replyTo⟺kind`、关联键改 taskId），旧 mail 与评审存量已归档
  （`artifacts/archive/org-v1-runtime-<date>/`）——验收判据不得建立在 v1 mail
  语义或 v1 评审 stage 面之上（12 Answer §4／§5／§7）。
- **证据面存续**：证据包链与 `preflight` 门② **存续**（AGENTS.md §2 长期
  纪律），验收实验的证据生成沿用该链、随批出增量包（12 Answer §5／Q9）。
