# org-v3 研究补核与委派

派发或验收本图研究工作包时，先读本文件，再读所属票的「可委派工作包」与原关闭判据。
本文件只细化本轮研究交付，不改变全局技能、长期纪律、S1–S5 或 HITL 裁定权。
2026-10-13 本轮完成派发准备，尚未启动 ds、认领或关闭研究票。

## 委派判断

本次 ds 交付适合继续用作检索线索和候选清单。来源覆盖较广，也披露了访问限制，
但支撑关闭的主张核验未完成。具体失败见形态、成本、理论三票 Comments，以及
[关键引用纠正](research/evidence-corrections-2026-10-13.md)。

| 已观察的问题 | 本轮交付与验收的对应要求 |
|---|---|
| 报告披露核心盲区，票却关闭 | 工作包交付、证据验收、整票关闭分开记录，关票由主会话按原判据处理 |
| 书目或摘要被用于支持正文机制和架构建议 | 主张、原文定位、作者边界与项目推断分栏；有题录不等于内容已核 |
| 未核验或访问失败被写成不存在 | 未核验与有界检索空结果分开，后者附范围与检索记录 |
| 对照臂、分母和量纲混淆 | 每组数字附两臂配置、任务分母、单位、原始单元格与复算式 |
| 报告、Answer 和地图互相矛盾，研究推荐替代用户选择 | 主会话统一引用强度和接口，主指标、阈值及架构取舍仍由 HITL 票裁定 |

这也包含建图和收口方的验收失守，不能只归因于采集方。判断限于本次交付，
不据此推断 ds 在所有研究任务上的能力。

ds 可承担有界的一手材料提取、表格补核和缺口记录。理论迁移、因果归因、
跨报告冲突裁决及最终验收留在主会话。若核验需要重做大部分推理，该包直接留在主会话。
各票的工作包只是候选分工，不构成整票外包，也不承诺节省净成本。

## 派发前

1. 主会话按 tracker 登记在办与领票，固定完整基线 commit。选一个票内工作包，
   列明需要补核的主张及原文候选，只传相关小节，不重复派发已经完成的纠正。
   完成条件是工作包有独立问题、来源范围、确切输出路径、逐项验收与停止条件。
2. 核对来源访问、工具能力和写入边界。采用 DSH Delegate 时，默认模型按技能选择，
   effort 保持 `max`，记录实际模型标识，不把别名直接当作原研究的 ds4.1 版本。
   - 已有本地来源快照时用 `read-only`，它只允许 read/glob/grep，不支持 shell、联网或落盘。
     ds 返回结构化证据，由主会话保存。
   - 需要自行联网时，`default` 才有对应工具；只有权限可限制在本包输出与获准来源时才使用。
     文字中的「只读」不能代替执行权限，改变 cwd 也不等于隔离。
   - 所有 DSH 模式都会写会话记录。启动前须有这些写入的明确授权，或验证记录落在获准的
     隔离位置；本轮没有新增运行面授权。条件不满足时不调用，不改真实配置凑条件。
3. 把简报中的仓库根、票面、来源快照和输出改为绝对路径。每包最多五条决策主张，
   只交一个 Markdown 补核件，正文含表格以 150 行为上限。来源原件不塞进正文。
   超限时交已完成项和剩余缺口，主会话再拆包，不删适用限制换取篇幅达标。
   完成条件是逐条可验收，不是填满行数或凑够来源数。

首次建议派[带成本的公开基准与成本口径](issues/02-research-benchmarks-with-cost.md)的
「同模型双数字」包，范围仅 BudgetMLAgent、Optima 两个既有候选，核实是否满足同集同模型
的双数字条件。待核对象和判据明确，适合先校准提取和验收是否有效。两者均不符合也可结束
工作包，但不能关闭研究票。首包验收通过后再扩量，不同时重跑全部研究票。

## 自包含简报

实际派发时填写以下字段，不直接把本模板当作已完成的派单：

```text
目标：<所属票题、工作包题、待核主张清单>
输入：<绝对 cwd、完整基线 commit、票面、此约定、来源或快照清单>
范围：<指定来源与问题；每个来源允许的替代官方入口；工具模式>
输出：<绝对路径 research/supplements/<票号>-<包名>-<批次>.md>
允许写入：<只此新补核件；read-only 模式改为只返回内容，由主会话落盘>
验收：<票内本包要求 + 下节证据字段 + 对应原关闭项>
停止：<来源不可达、原文冲突、工具越界、达到工作量或超时界限时如何交回缺口>
```

补核件独立新增。ds 不改原报告、票状态、地图、关闭判据或 Git；主会话验收后再整合。
沿用 research 技能的一手追溯要求，由该工作会话完成，不再嵌套委派。
本轮研究只读材料，不运行论文代码、基准实验或真实模型试验，不安装依赖，不写真实运行面。

## 每条证据的最小字段

| 字段 | 必填内容 |
|---|---|
| 主张与用途 | 本包内稳定 ID、待证原句、所属关闭项及下游票；一行只支持一个结论 |
| 来源定位 | URL、作者或机构、版本或 commit、采集日期；页码、章节、表行或源码符号；本地快照路径与 SHA 若已保存 |
| 实读层级 | 全文、摘要、书目、官方数据或原判据允许的权威二手；给最短支撑摘录或表格单元格 |
| 证据结论 | 支持、反驳、有界检索未发现、未核验或冲突未决；记录限制，访问失败归未核验 |
| 作者与项目边界 | 作者报告、独立算术复算、项目推断分别标注；本轮无独立实验复现，不把论文报告写成项目已验证 |
| 量化附项 | 两臂的模型、版本、工具、任务集及分片、尝试数与成功数、预算和采样策略、计量单位与分母、聚合与不确定性、原数字和算式 |

非量化条目将量化附项标为不适用，不编造数值。量化来源缺字段时逐项标未知，
不能填零。成本另标公布值或账单复算，说明 token 字段包含关系、价格日期、失败重跑、
路由、搜索与筛选开销。百分点、相对百分比、token 倍数和美元倍数分别记录。

补核件末尾给「原关闭项覆盖表」与「剩余缺口」。有界空结果附检索词、官方入口、
检索日期、已读范围与失败路径，只对这个范围下结论。原判据没有空结果退路时，
空结果能结束工作包，不能关闭票。来源冲突并列记录，主会话裁决后才统一结论。

## 验收与返工

1. 主会话核对实际返回内容和落盘件，工具调用成功只代表会话结束。首包逐条回读原文；
   后续包中支撑关闭、S2/S3、因果比较或争议项的证据同样逐条核验并独立复算。
   其余背景项可抽检，发现同类错误则退回该类条目，不把抽检写成全量核实。
2. 以本次失误作拒收反例：不同模型榜单比不能满足同模型组织对照；摘要未提某词不能
   证明正文无该机制；一次路由开销不能代替完整迁移成本；算术比正确不能证明账单正确。
   任一命中，受影响结论不进入 Answer。原始来源仍可保留为线索。
3. 核对同一数字和 C1–C9 等引用在报告、Answer 与消费者中的含义一致，再整合报告。
   验收记录写明通过项、拒收项、证据路径与未核项；整合由主会话完成，不由采集方自验收。
4. 机械路径或格式错误在本地修。语义问题最多做一次有针对性的返工，且重派与验收仍须
   比接管更省工作；再犯、需重做推理或遇核心资料不可达时，主会话接管或保留缺口。
5. 关闭研究票前逐条回到原关闭判据与 S4，核心未核、冲突未决即保持开放。
   合法空结果只沿该票原有退路处理。主会话登记 Answer、关闭状态与地图指针，
   研究人员的完成声明不触发自动关票。

每包记录实际模型、工具模式、session_id、用时、可得的 token 用量、返工次数和验收结果。
主会话另记交接与核验开销；未计量项标未知。没有同任务本地基线时不报告净节省。
